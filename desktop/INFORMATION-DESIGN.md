# 画面の情報整理（2026-11-22）

## 判定軸と範囲

`README.md` のDesktop節と `desktop/README.md` を要約した判定軸は、「Macアプリの開発者がストアへの配信準備で、案内に沿って作業と確認結果を残し、次の一手を把握して再開できること」。コンセプト自体の変更は行わない。

- 誰：Macアプリの開発者。
- 場面：審査準備からアップロード・審査・公開確認まで。
- 行為：必要な作業を進め、根拠と状態を記録する。
- 目指す状態：残っている確認と、次にすることが分かる。
- 優先する価値：未確認を完了にせず、中断後も再開できること。

対象は案件一覧・登録/編集、7工程、サンプル、エラー復旧。評価単位は同じ意味を伝える情報ブロックとし、その中の入力欄やボタンを別々に加算しない。操作可能な機能の廃止、判定条件、保存形式、監査ルールの変更はない。

## 量の比較と配置

同じ架空案件（版1.0、ビルド1、日本語、JP、未監査）で比較。作業枠は画面全体のフォーム単位、AXの数値はスクロール内全域のアクセシビリティ表現を同じ処理で抽出した近似値。AXはURL・代替名・画面外要素も含み、スクリーンショットの可視文字数とは異なる。可視文字数の厳密な実測は未実施。

| 指標 | 前 | 後 |
| --- | ---: | ---: |
| 監査工程で同時に配置する作業枠 | 7 | 1 |
| 掲載準備で同時に配置する作業枠 | 3 | 1 |
| 監査工程のAX文字数 / ノード数 | 967 / 26 | 89 / 9 |
| 掲載準備のAX文字数 / ノード数 | 575 / 31 | 200 / 25 |
| 7つの画面実装の先頭UI文字列（コード上の参考値） | 4,271 | 3,562 |
| 独自に指定した見出しサイズ | 27・28の2種 | 0（largeTitleへ統一） |
| フォントAPIの種類 | 10 | 9 |
| 新しい色・角丸・影 | — | 追加なし |

コード上の文字列参考値は `Text/Button/Link/Label/TextField/DisclosureGroup/WorkCard/WorkDetails/Picker/Toggle` の先頭の文字列リテラルを同じ正規表現で数えたもの。動的文面を展開した総文字数ではない。選択肢の総数は減らさず、工程内の切り替えとメニューへ分けた。監査は種類3択→手動項目5択、掲載準備は作業3択となる。必須入力の数と必要な判断は維持する。

案件と工程→今の作業→主操作→補助情報の順に配置。デスクトップの主要ボタンは対応する入力/結果の直後、保存/キャンセルはシート末尾の既存位置を使う。開閉欄は標準DisclosureGroupの短い展開に統一し、OSの動きを減らす設定では追加アニメーションを無効にする。監査中は工程内の切り替えを無効にし、二重実行を防ぐ。

サイドバーと本文の工程名はナビゲーションと現在地の見出しとして残す。ビルド識別情報を提出確認シートで照合する再表示は、別アプリ/版の誤記録を防ぐ確定前の確認として残す。履歴を自分で開いた場合も再表示の例外とする。
